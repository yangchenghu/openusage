# 0.7.16 厂商用量兼容维护

## 结论

保留 `release/0.7.16` 的界面，按修复内容移植，避免整体合并 main。
Cursor 已额外移植 main 的独立浏览器授权；其余厂商保留原登录来源。
main 已重写账号、布局、历史统计和刷新架构，不能直接替换整个 Providers 目录。

对比基线：`release/0.7.16` 的 `abf472d` 与 2026-11-13 拉取的 `origin/main` `c6c14f7`。
这里描述的是该次 main 快照；不代表所有变化都已包含在正式版 0.8.0 中。

## 本次移植的来源

- Cursor 预算隔离：main `b3f6e79`（#1661）。个人限额不能配团队支出，团队限额不能配个人支出。
- Cursor 空历史列表：采用 main `CursorUsageEvents` 对缺省事件列表的兼容方式，保留原有分页完整性检查。
- Cursor 通用请求计数 fallback：参考 main `AccountProviderRuntime+CursorUsage.swift`，用同一个 summary mapper 同时填入 Total Usage 和 Requests，并保留历史读取，避免数据只落入默认隐藏的 Requests 指标。
- Cursor JWT 续期：参考 main `AccountProviderRuntime+CursorAuth.swift`，适配原有本机凭证流程；只在没有独立 refresh token 且访问令牌可解析为带 subject 的 JWT 时使用。
- Antigravity 主机顺序：main `ee98159`（#1641）。只改变云端摘要读取，不改变本机来源或指标默认值。
- Grok 金额：main `b7d81db`（#1657）。例如原始 `2500` 显示为 `$25.00 cap`。
- Z.ai 业务错误：main `a67a783`（#1543）。HTTP 成功不等于密钥验证成功。

以上为针对旧架构的移植，没有直接 cherry-pick 整个新版账号系统。

## Cursor 独立授权补充

用户确认第一批兼容修复后仍不能读取 Cursor 用量，因此继续移植 main 的浏览器登录。
入口为 **Customize → Cursor → Account → Sign In…**。授权协议来自 main 的
`Services/DeviceProviderLogins.swift` 中的 `CursorLogin`：

- `cursor.com/loginDeepControl` 打开登录/授权，携带随机 uuid 和 PKCE challenge。
- `api2.cursor.sh/auth/poll` 用同一 uuid/verifier 轮询，最多等待五分钟。
- 获取新令牌后用新令牌验证主用量接口，成功后才替换 OpenUsage 的已保存账号。
- 令牌保存到 OpenUsage 自己的 Keychain 项目，优先于 Cursor 本机登录，不写 Cursor 的数据库。
- 续期遵循 main 的 JWT 规则，保存失败时保留内存中的新令牌并明确提示、重试。
- 切换登录时清除旧账号的展示缓存，避免历史读取尚未完成时保留另一个账号的数据。

此移植只接入一个 Cursor 授权账号，不引入 main 的多账号界面、Tab 或动态状态栏排序。

## Cursor 旧版失败还需要区分什么

目前没有取得原失败的错误日志，不能断言上述修复就是该账号无法更新的根因。
新旧版本调用相同的主用量接口，但凭证来源不同：新版独立登录成功，只能说明新登录
可访问接口，不能证明旧版读取到的 Cursor 本机令牌仍然有效。

- 登录过期、401/403：先检查 Cursor 应用自身登录状态。只有访问 JWT 的本机会话现在可以尝试续期。
- Total Usage 可读而历史一直无数据：缺省空事件列表会阻止旧版凑齐 30 天，本次已修复。
- 已拿到请求计数但 Total Usage 无数据：通用备用路径此前只填 Requests，现在同时填入原有 Total Usage，指标的默认开关及位置不变。
- Team/Enterprise 数值不合理：本次修复个人与团队预算混算；原有模型池及 REST fallback 保留。
- 仍无法刷新：从应用诊断日志确认失败的端点和状态码，避免盲目替换整个登录系统。

## 状态栏顺序

main 的状态栏按 Priority 规则组织，会根据额度紧迫程度变化；当前 main 默认最多显示 3 项，
其余折叠为计数。这不是固定的厂商顺序，也是它与旧版体验不同的原因之一。
这些是当前 main 的行为，未逐项核对正式版 0.8.0 的默认值。

本分支仍按 Customize 的厂商/指标顺序显示已加星项，Always Visible 项在 On Demand 项之前。
默认厂商顺序为 Claude、Codex、Cursor，其余按名称排序；已有自定义顺序优先。
